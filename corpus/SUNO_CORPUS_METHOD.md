# Suno Experimental Corpus: Method and Data Model

**Initial dataset snapshot:** 2026-11-02  
**Purpose:** Analyze relationships among musical instructions, generated outputs, and subsequent human evaluation without treating generator-produced descriptions as ground truth.

## 1. Source snapshot and limitations

The initial input is a user-supplied Suno library JSON export. The source contains 1,740 unique complete clip records, 1,798 directly observed song links, 2,174 candidate IDs checked, and 92 observed feed pages. The feed cursor remained nonempty at export time. The export reports three studio API `Too many requests` warnings. It is therefore a best-effort snapshot, not a complete census of the account.

The raw export intentionally contains no authentication token. Raw prompts, lyrics, descriptive tags, account identifiers, and audio URLs remain private and are not committed to this public repository.

## 2. Record types are not interchangeable

The export includes multiple record types. In the initial snapshot:

| Type | Records |
|---|---:|
| `gen` | 1,552 |
| `upload` | 116 |
| `studio_export` | 47 |
| `preview` | 10 |
| `concat` | 10 |
| `upsample` | 4 |
| `edit_speed` | 1 |

A clip is not necessarily a finished song. Very short uploads, sound effects, previews, long-form recordings, and derived exports should not be pooled without an explicit task-specific reason.

## 3. Evidence layers

Every claim about a clip should keep these evidence classes separate:

- **Source instruction:** Original prompt or supplied source material.
- **Generator description:** Tags or summaries generated by Suno. These are model outputs, not independent ground truth.
- **Measured audio feature:** A feature calculated from the audio, with algorithm, version, parameters, and confidence recorded.
- **Human evaluation:** A listener's assessment, ideally tied to timestamps and a defined rubric.
- **Inferred interpretation:** A hypothesis about genre, instrument, rhythm, form, or performance, with uncertainty and supporting evidence.

Missing metadata means unknown, not absent. A generated tag that says "gamelan" does not establish that the audio contains a gamelan instrument or tradition.

## 4. Relationships and experimental units

Do not use title equality or timestamp equality as the sole criterion for experimental lineage.

The corpus can contain several distinct relationships:

1. **Repeated prompt:** Exact prompt text reused, identified by a cryptographic hash.
2. **Candidate generation batch:** Records that share title and/or timestamp. This is a discovery hint, not proof of a common generation request.
3. **Explicit derivation:** Records whose metadata names task type and source clip IDs, such as mashups.
4. **Cross-version replication:** The same prompt reused under a different model/version or different settings.
5. **Transformation:** Cover, extend, infill, upsample, or other task-specific relation.

A controlled comparison requires checking the prompt, model, mode, settings, source references, and task. Change one variable at a time when testing a causal hypothesis. Otherwise describe the comparison as observational.

## 5. Initial coverage findings

From the 2026-11-02 snapshot:

- 1,740 unique clip records.
- 533 exact-prompt hash families containing 1,440 records.
- 119 explicit task/source relationship groups containing 647 records.
- Average BPM present on 1,044 records; key present on 465.
- No populated time-signature field in this export.
- Recorded duration spans 1.8 to 1,322.67 seconds; median 215.84 seconds.

These counts describe this exported snapshot, not the full Suno account.

## 6. Sanitized local analysis package

The accompanying analyzer writes:

- `corpus_summary.json`: source checksum, export completeness, counts, and interpretation cautions.
- `clip_index.json`: one sanitized row per clip, preserving clip IDs and metadata fields but omitting raw prompts, generated tags, identifiers, and media URLs.
- `prompt_families.json`: exact-prompt SHA-256 families and associated clip IDs, dates, tasks, and model versions.
- `derivation_groups.json`: explicit task/source relationships and output clip IDs.

These local outputs remain private by default. Do not upload them to the public repository without a separate privacy, publication, and rights review. Even hashed prompt groups can reveal activity patterns when combined with public song links.

## 7. Suggested first research questions

1. What variation occurs among outputs generated from the same prompt and materially identical settings?
2. How does output change when the same prompt is reused across model versions?
3. Which musical instructions are preserved, ignored, or transformed in the audio?
4. How reliable are generated tags as descriptions of audible structure?
5. Which prompt constructions communicate independent cycles, accent relationships, vocal handoffs, or instrumental roles most reliably?
6. How do human preference and measured prompt adherence relate, and where do they diverge?

## 8. Minimum experiment record

A future experiment record should include:

- experiment ID and hypothesis;
- input clip IDs and prompt hash;
- raw prompt location in the private source store;
- model/version, generation mode, sliders, task, and date;
- source/reference clip IDs;
- output clip IDs and checksums where available;
- audio analysis software/version and measured features;
- human evaluations and timestamped observations;
- changed variables and known confounds;
- conclusion and confidence.

Do not infer missing settings from defaults or model version alone.

## 9. Privacy and rights

The public repository stores code, schemas, methods, and appropriately cleared examples only. Do not commit raw conversation exports, complete library exports, copyrighted lyrics, private source recordings, account identifiers, authentication data, or direct media URLs. User-authored material also remains private until explicitly approved for publication.
