# 04 — Prompt Grammar

Not a command language: a character-efficient relational notation for shaping a possible song.

## Fields

- **Styles:** global song-world, engine, priorities, source ontology, persistent states, trigger declarations, broad trajectory.
- **Lyrics/plain:** vocal-eligible text; phrase geometry; temporal skeleton; exact anchors.
- **Lyrics/brackets:** local/regional structural, sonic, performance or production pressure.
- **Exclude:** secondary boundary against specific fallback resolutions; never primary architecture.
- **Settings:** interpretation regime; always logged.

## Minimal relations

IDENTITY | CONTAINMENT | COEXISTENCE | SEQUENCE | TRIGGER | PERSIST | ACCUMULATE | TOGGLE | TRANSFER | SWAP | CLEAR | RESET | RETURN | VIOLATE

Syntax has no presumed fixed operators. It earns characters only by clarifying relationships.

## Placement principle

Global only when global. At use-site, favor:

`OBJECT → BEHAVIOR → ANCHOR/LOCATION → PERSISTENCE/TERMINATION`

Example conceptual form:

`[FRICTION@"if missing": late jaw-harp pickup against unchanged bone pulse; persists until "return packet"]`

## Grouping principle

- Group shared simultaneous state.
- Separate events that should register independently or sequentially.
- Do not rely on multiline bracket scope, indentation or formal code semantics.
- Repeat the musical consequence more often than the abstract label.

## Rupture operators (conceptual, not executable)

BOUNDARY_COLLAPSE | CONTRADICT | OVERLOAD | MALFORM | FALSE_SCOPE | IMPOSSIBLE_OBJECT | ROLE_LEAK | TOKEN_CONTAMINATION | GRAMMAR_BREAK | INCOMPLETE_RETURN

## Audit pair

- **Wiring audit:** can the intended relationships be inferred locally?
- **Rupture audit:** has enough ambiguity/pressure been preserved for model contribution?
