# HATCHLINGS

A four-book speculative novel by Nathan Bellomy.

**Status:** Project archive established; source ingestion and version reconciliation in progress.

## Project architecture

This project preserves the organization and working logic of the original Scrivener project while making the material accessible as a navigable repository.

- [Manuscripts](MANUSCRIPTS/README.md): dated manuscript snapshots and book-level texts.
- [Scrivener archive](SCRIVENER_ARCHIVE/README.md): original project archive and recovered binder structure.
- [Research](RESEARCH/README.md): language, culture, science, setting, and other research.
- [Planning and notes](PLANNING/README.md): character guides, structural notes, schedules, continuity pins, and project analysis.
- [Source register](SOURCE_REGISTER.md): provenance, dates, status, and relationships among source files.
- [Copyright](COPYRIGHT.md): rights statement for this project.

## Working assumptions

1. The January 2025 manuscript files are the presumptive latest textual baseline supplied so far.
2. The 2017–2018 Scrivener project is an earlier, richer working archive, likely containing notes and organizational context absent from the later manuscript exports.
3. These are working hypotheses, not yet a verified version history. Compare before reconciling.
4. Preserve source files verbatim. Do not overwrite an earlier version with a later one, silently normalize wording, or discard material merely because it is absent from the current manuscript.
5. Treat the Scrivener binder as the organizational reference. Improve navigation without flattening its distinctions.
6. Additional Hatchlings documents may exist and should be incorporated with their provenance intact.

## Repository conventions

- Preserve original filenames in an intake/archive layer.
- Use descriptive, stable filenames for curated working copies.
- Mark dates and version status explicitly.
- Keep authorial notes distinct from manuscript text and research evidence.
- Flag uncertainty rather than resolving it by guesswork.
- Keep a change log for substantive editorial or structural decisions.
